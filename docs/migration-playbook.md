# 从 Topinspo 迁移成一个投资者站点：全过程复盘与坑点清单

> 项目：MangoSource（https://lj22503.github.io/mangosource/）
> 时间：2026-11（约两周，含反复重写）
> 用途：给下一个项目（**买方投顾**）当施工手册，避免重复踩坑。

---

## 一、一句话结论

**真正难的不是"把设计站抄过来"，而是重新回答四个问题：**

1. 这套结构里哪一层在金融里会死？（答：看图那层）
2. 用户的入口是哪句话？（答：群里那句抱怨，不是我们的分类）
3. 每条内容的最小可用单元是什么？（答：一句判断 + 一步动作，不是一篇文章）
4. 它替用户解决了哪个动作？（答：不是"学习"，是"现在要不要动手"）

这四问答错，页面做得再像也是空壳。

## 二、踩过的坑（按项目阶段）

### 阶段 1：拆解

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **只看到"内容量"，没看到"结构"** | 第一版拆解写的是"525 条素材 + 227 句判词 + 怎么导流" | 把内容当成了可迁移的部分 | 可迁移的只有三样：**能力分层 / 名词+一句定位+可执行动作 / 感觉→参数→指令**。内容量不可迁移 |
| **只信截图，不验证结构** | 层内数量、分组、路由全猜错（应为 8 个分类、11 组工具、4 个真实 URL） | 截图看不到路由与数据层 | 拆解必须抓一次真实 HTML/JS：路由数、数据结构、详情是页面还是弹层 |

### 阶段 2：迁移与定位

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **照搬五层，第一层直接死** | 「灵感层」要图、要版权、要脱敏；金融的 KPI 也不是"好看" | 直接对应栏目，没有换血 | 迁移先做"层替换表"：哪层留、哪层换、哪层是命。金融必须换成「场景层」 |
| **用五个抽象动词做导航** | 用户看不懂"说不清/算不清/看不清" | 那是**信息架构师的语言**，不是用户的语言 | 入口文案必须是**用户原话**（"这个能买吗""跌了要不要割"），分类留在后台 |
| **五个产品并列 = 没人点** | 菜单式入口，用户站在门口不知道进哪个 | 选择过载 | 只做"分诊"：一句问 + 一个默认推荐 |
| **把站点当成官网做** | 反复改视觉、加图片、抄设计站细节 | 没先定"它是回答库还是官网" | 先定目标：**被收藏 > 被转发 > 加圈子**。回答库重搜索与复制，官网重品牌与故事 |

### 阶段 3：内容

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **内容写"归纳过的"，不是"用户原话"** | 场景卡写成"基金跌了 8% 我想卖"，群里其实是"要不要割" | 用自己的框架替代了用户的词 | 场景标题抄群聊原文；解法才用我们的框架 |
| **"简化得太厉害"** | 大师卡只留一句理念，用户觉得空 | 把"精简"当成了"省略证据" | 每位大师必须给：**理念 + 战绩（数字）+ 三条能学的 + 去哪读** |
| **链接指向二手总结** | 链到知乎/雪球的总结帖，用户不满意 | 只想着"有链接就行" | 只认三类链接：**官方一手 / 本人账号 / 书**。没有就自己写（站内读书卡），并标注"暂无公开资源" |
| **指向官网首页** | 点"博格"进先锋首页，等于没给 | 用公司首页凑数 | 链接要指向**那一份内容**：年报档案、备忘录列表、某本书的阅读页 |
| **工具层全是官网/销售平台** | 一屏都是银行、基金公司 | 没做淘汰标准 | 收录标准写死：① 解决一个具体痛点 ② 国内可用 ③ 免费优先 ④ 说清它不做什么 |

### 阶段 4：设计

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **一上来就改版** | 连续三轮"改完更差" | 没先对齐参照物，靠感觉调 | 先复制参照站的**实测数值**：h1 20px/500、tabs 14px/间距 24/2px 高亮、导航 38px 行高、圆形按钮 36px |
| **在同一站混用四种组件** | 卡片、行列表、小词卡、大卡混着来 | 每层各写各的 | 全站一套卡：**顶部（类别+↗）/ 标题 / 一句 / 底部（来源+数字）**；只有工具/清单用行列表（信息密度高） |
| **把内部说明放到页面上** | 侧栏写"国内直连/需梯子/收录标准/中立声明" | 把自己的 QA 清单当成了产品文案 | 产品页只留用户需要的信息；方法论放进 README 与本文档 |
| **分隔线泛滥** | 每段前面一条线、虚线框一堆 | 用线代替层级 | 层级靠字号与留白；线只在必要处（tabs 下沿、页脚） |

### 阶段 5：技术

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **手机端没做** | 左侧栏在手机上挤成一列，工具行中列被压到 24px | 只按桌面调 | 断点 900px：顶部栏 + 抽屉；工具行改上下堆叠；tabs 单行横滑（`nowrap` + `overflow-x:auto`） |
| **JS 报错导致整页空白** | Skill 页只有 tabs，下面全空 | SKILLS 数组里混进了两个大师对象 → 解构报 `object is not iterable` | 数据写入后加一条**自检**：每条必须是数组且长度固定；改数组结构必须跑一遍全页面 |
| **变量名错误只在运行时炸** | `data-track-sub` 用了不存在的 `n` | 批量替换时没检查上下文变量 | 批量替换后必须 `node --check` + 逐页真机点一遍 |
| **SSH 推送偶发被重置** | `Connection reset by ... port 443` | 网络抖动 | 重试循环（3–5 次，间隔 5 秒）就够了，别换协议 |
| **Pages 开不了** | 仓库私有 + gh 未登录 | 免费账号私有仓库不支持 Pages | 项目一开始就定：**公开仓库 + Pages**，或直接 Cloudflare Pages |
| **标题忘记改** | 上线后 title 还是"投资资源地图…" | 只改了界面文案 | 发布清单加一条：title / description / og 图 |

### 阶段 6：发布与运营

| 坑 | 现象 | 根因 | 下次怎么做 |
|---|---|---|---|
| **没有埋点** | 完全不知道用户点哪 | 一直往后拖 | 第一天就埋：`page_view / nav / 内容打开 / 复制 / 外链 / 加圈`，命名与主站一致（`cta_click`） |
| **归因参数没统一** | 主页跳过来没带 `?ref=` | 每个项目各写各的 | 统一 `?ref=<入口>`，埋点里透传 ref 与 utm |
| **"敬请期待"点不动** | 点了没反应 | 禁用态没给反馈 | 悬停/点击在**点击位置旁边**浮出提示，不要放到屏幕底部 |
| **主页挂了死链** | 主页加了新站链接，但 Pages 还没开 | 上线顺序错 | 顺序：先开 Pages 验证 URL 200，再在主页加链接 |

## 三、最终成型的结构（可直接复制）

```
七层（按用户动作，不按内容分类）
├─ 投资场景   21 条：为什么卡住 → 三步解决（第 3 步是提示词）→ 现在就做一件
├─ 投资工具   44 条长清单：官方披露 / 行情 / 数据估值 / 研报 / 基金 / 监管自查 / 银行保险 / 港美股 / 数据终端 / 开源量化
├─ 投资大师   19 位 × 6 派别：理念 + 战绩 + 三条可学 + 书/官方入口
├─ 投资 Skill 52 个 × 10 类：GitHub/SkillHub 真实仓库，标作者与 star
├─ 投资词典   9 类身份 × 12 词：先认你是谁，再给你该懂的词
├─ 投资提示词 6 条 × 6 个"你会问的那句话"：一键复制，say to AI
└─ 投资工作台 敬请期待
```

**四个可复用的构件：**

1. **场景卡三层解法**：为什么卡住（2 条）→ 三步（查 / 判 / 让 AI 算）→ 现在就做一件。第三层永远是提示词，这是"轻"的关键。
2. **大师卡四段**：理念（一句）→ 战绩（数字与时间）→ 三条可学 → 去哪读（书 / 官方）。
3. **词卡墙**：先 persona（我是什么用户）→ 三条"你要先搞懂"→ 12 张词卡 → 点进词典。
4. **提示词条目**：类别（你会说的那句话）+ 标题 + 一句作用 + 全文（角色/输入/任务/约束/输出）+ 它会给你什么。

## 四、给「买方投顾」的迁移清单

买方投顾和这个站的差别：**从"给资源"变成"给决策"，从"免责"变成"受托"**。所以：

### 可以直接复用
- 场景层骨架（为什么卡住 → 三步 → 现在就做一件），但把"让 AI 算"换成"和顾问确认"
- 提示词六条（能直接变成顾问的提问脚本 / 客户沟通模板）
- 工具与大师清单（顾问自己也要用）
- 埋点方案与 `?ref=` 归因

### 必须换掉
| 这站的做法 | 买方投顾不能这么做 | 应该改成 |
|---|---|---|
| "不荐股、不预测" | 投顾必须给建议，但要**有依据、有适当性、有留痕** | 每条建议带：依据、假设、最坏情况、复核周期 |
| 匿名化、不点名机构 | 投顾要**明确谁在提供服务、谁承担什么责任** | 每页页脚放：持牌主体、编号、投诉渠道 |
| 内容型入口（"这个能买吗"） | 投顾的入口是**客户画像与目标** | 入口改成：你的钱多久要用 / 能承受多大回撤 / 想要什么现金流 |
| 场景卡"三步" | 投顾的"三步"必须包含**记录与复核** | 三步：诊断 → 方案（含适当性）→ 定期复核（写进流程） |
| 免登录、纯静态 | 投顾要留痕、要能回溯 | 需要账户体系 + 操作日志 + 建议版本 |

### 三个提前想清楚的问题
1. **你要做"投顾的工作台"还是"投顾给客户看的站"？** 两者的信息层级完全相反。
2. **建议怎么留痕？** 没有留痕，就没有受托责任的证据链。
3. **适当性怎么落？** 不是一张问卷，是"这个产品为什么适合这个人在这个时点"。

## 五、下次开工的顺序（照着走）

1. **定目标**（收藏 / 转发 / 加圈，选一个主目标）
2. **定入口语言**（抄用户原话，20 条起）
3. **定单元格式**（一条内容 = 哪几个字段，固定下来）
4. **搭壳**（左栏 + tabs + 一种卡片，先做 3 条假数据）
5. **填一条真的**（从场景层开始，做透一条再复制）
6. **手机先测**（390×844，先测手机再测桌面）
7. **埋点**（第一天就埋）
8. **发 Pages**（先验证 200，再挂主页链接）
9. **收集真实提问**（群聊截图），回去改标题，不改结构

## 六、一句话给未来的自己

> **结构可以抄，判断不能抄；页面可以像，入口必须是用户的原话。**
> 每加一个栏目，先问一句：它会让我更快地回答"我现在该做什么"吗？
